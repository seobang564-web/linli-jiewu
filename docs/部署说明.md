# 云服务器部署说明

适用于腾讯云轻量应用服务器，Ubuntu 22.04、JDK 17、MySQL 8，建议至少 2GB 内存。
第一周验收使用 `/api/hello` 和 `/api/health`；物品接口尚未实现，不用 `/api/items` 判断初始化成功。

## 1. 首次准备

腾讯云实例“防火墙”放行 TCP 8080，SSH 22 仅允许成员所需的来源 IP，3306 不向公网开放。
系统自身启用防火墙时也需允许 SSH 和 8080，确认保留 SSH 访问后再调整规则。

在服务器终端安装运行环境：

```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo apt update
sudo apt install -y openjdk-17-jre-headless mysql-server unzip curl python3 openssl
sudo systemctl enable --now mysql
java -version
mysql --version
```

仅在空数据库首次安装时执行 `数据库设计.sql`、创建 MySQL 用户并授权。
如果已经看到 `users/items/borrows/borrow_logs/conversations/messages` 六张表，直接跳过建表步骤。
Linux 的 `linli` 服务用户与 MySQL 的 `linli` 数据库用户彼此独立。
部署脚本不会执行 SQL、建表、重置数据库密码或重建数据。

## 2. 本地构建及打包

在仓库根目录 PowerShell 7 中执行：

```powershell
.\scripts\Build-Week1.ps1 -Component Server
.\scripts\Package-Server.ps1
```

真实输出文件为 `.artifacts/linli-week1-deploy.zip`，包含可执行 `app.jar`、无密钥配置模板、部署脚本、systemd 单元和 SHA256 校验清单。
本地全套验证用 `.\scripts\Build-Week1.ps1`，包括 Android 编译、网络单元测试和 Lint。

## 3. 上传部署包

在本机 PowerShell 通过 `scp` 上传上述真实 ZIP 到服务器 `/tmp/linli-week1-deploy.zip`。
服务器 IP、登录用户按本人实例填写；不要原样执行带占位符的示例，也不要把上传命令当作构建命令。
上传后进入服务器终端执行以下无占位符命令：

```bash
mkdir -p /tmp/linli-week1-deploy
unzip -o /tmp/linli-week1-deploy.zip -d /tmp/linli-week1-deploy
sudo bash /tmp/linli-week1-deploy/deploy.sh
```

脚本校验文件、确认 JDK 17 和 MySQL，创建无 sudo 权限的 `linli` Linux 服务用户。
首次运行会让你在终端隐藏输入数据库用户 `linli` 的密码，同时本机生成 JWT 密钥。
敏感环境配置存 `/etc/linli/server.env`（root、0600），JAR 和生产配置由 root 管理，服务用户只读，图片目录允许服务用户写入。
普通更新沿用现有环境配置；数据库密码修改后可加 `--configure` 重新输入，此参数也会生成新的 JWT 密钥，后续启用登录后会使旧 Token 失效。

脚本启动 systemd 服务，配置开机自启，并检查本机 Hello 和数据库健康状态。
数据库检查失败时先检查密码、权限和表，不要删除数据库或重复建表。
旧 JAR 在替换前保存为 `/opt/linli/app.jar.previous`。

## 4. 公网验收与 Android 配置

在本机 PowerShell 运行 `scripts/Verify-Server.ps1 -BaseUrl`，参数填写真实 `http://公网IP:8080/api/`。
两条输出均为 PASS 才表示公网与数据库验收通过。
本机 curl 成功但公网超时，应检查腾讯云防火墙、系统防火墙及监听端口。

Android 的 `local.properties` 设置相同的 `server.baseUrl`，保留末尾 `/api/`，重新编译并安装后点击“检查服务连接”。
WebSocket 地址保留为 `ws://公网IP:8080/ws`，聊天推送按第 4 周计划实现。

## 5. 运维命令

```bash
sudo systemctl status linli --no-pager
sudo journalctl -u linli -n 100 --no-pager
sudo systemctl restart linli
curl -i http://127.0.0.1:8080/api/hello
curl -i http://127.0.0.1:8080/api/health
```

同一实例后续更新只需重新构建、打包、上传并执行部署脚本，保留数据库和上传图片。
上线报告须说明 HTTP/WS 明文限制；正式上线应改为 HTTPS/WSS。
