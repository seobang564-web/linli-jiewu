# 开发约定

所有成员开工前阅读。约定变更需在周会上通过，并在本文件末尾的“变更记录”登记。

## 1. 已确定的项目决策

| 事项 | 决定 |
| --- | --- |
| 客户端语言 | Java + XML 布局（不使用 Kotlin / Compose） |
| 服务端部署 | 云服务器，通过公网 IP + 端口访问，**不使用域名与证书，传输为 HTTP / WS 明文** |
| 即时聊天 | 纳入本期；会话按“物品 + 借用者”建立，REST 发送消息，WebSocket 推送，断线时轮询兜底 |
| 待确认申请超时 | **12 小时**后自动取消，物品恢复可借 |
| 交接联系方式 | 以站内聊天为主；联系方式字段可选，仅在申请被接受后对双方可见 |

> 明文传输是已知限制，最终报告“安全设计”一节需如实说明，并写明正式上线应改为 HTTPS。

## 2. 包名与命名

- Android 包名（applicationId）：`com.linlijiewu.app`（高德 Key 绑定包名，确定后不可再改）
- 服务端根包：`com.linlijiewu.server`
- 数据库名：`linli_jiewu`，表名、字段名使用小写下划线
- JSON 字段使用小驼峰（`pickupLat`、`distanceM`）
- 枚举值使用大写下划线（`AVAILABLE`、`BORROWING`），定义以 `docs/接口文档.md` 为准

## 3. 分支与提交

- `main`：始终可编译、可运行；**禁止直接推送**，只能通过 Pull Request 合并。
- 功能分支：`feature/<姓名拼音>-<功能>`，例如 `feature/fangshuyu-map-search`。
- 修复分支：`fix/<姓名拼音>-<问题>`。
- 每个 PR 至少由一位其他成员审查通过后再合并；PR 描述写清：做了什么、关联任务、如何测试、截图（界面改动必附）。
- 提交信息格式：`<类型>(<模块>): <说明>`，类型取 `feat` `fix` `docs` `refactor` `test` `chore`。
  - 例：`feat(borrow): 实现接受申请的事务与状态校验`
- 每人用**自己的 GitHub 账号和本机 git 身份**提交自己负责的模块，不代他人提交。
- 每周五合并后打阶段标签：`v0.1`、`v0.2` …

## 4. 接口变更流程

1. 先修改 `docs/接口文档.md`，单独提 PR 或在同一 PR 中放在第一个提交。
2. PR 标题加 `[接口变更]`，并 @ 受影响的成员。
3. 前后端都按文档实现，**文档与代码不一致时以文档为准**，发现不一致先改文档再改代码。

## 5. 代码规范

### 通用
- Java 17，缩进 4 空格，UTF-8 编码。
- 类名大驼峰，方法与变量小驼峰，常量全大写下划线。
- 不提交被注释掉的大段代码、调试用的 `System.out`。

### 服务端
- 分层：`controller` → `service` → `mapper`；业务规则与状态校验只写在 `service`。
- 所有修改类操作在 service 中加 `@Transactional`，锁顺序固定为**先物品行、后订单行**（`SELECT ... FOR UPDATE`）。
- 统一响应结构与错误码见接口文档；异常通过全局 `@RestControllerAdvice` 转换，不在 controller 里拼错误 JSON。
- SQL 一律使用参数绑定（MyBatis `#{}`），禁止 `${}` 拼接用户输入。
- 操作人身份只从 Token 解析，**不信任**请求体中的 userId。

### Android
- 包结构：`ui/<页面>`（Activity / Fragment / Adapter）、`data/remote`（Retrofit 接口与 DTO）、`data/local`（SQLite）、`data/repository`、`util`。
- 网络请求不在主线程；页面统一处理“加载中 / 成功 / 失败 / 空”四种状态。
- 搜索请求带递增序号，只渲染最新序号的响应（防止旧结果覆盖新条件）。
- 字符串放 `strings.xml`，颜色放 `colors.xml`，物品状态颜色统一定义一次。

## 6. 密钥与配置

- **禁止提交**：高德 Key、数据库密码、JWT 密钥、服务器 root 密码。
- 高德 Key 写在 `android/local.properties`（已被 .gitignore 忽略），通过 `manifestPlaceholders` 注入。
- 服务端敏感配置写在 `server/src/main/resources/application-prod.yml`（已忽略）或环境变量；仓库只提交 `application-example.yml` 模板。
- 统一使用仓库内 `android/keystore/debug.keystore` 作为 debug 签名，保证三人 SHA1 一致，只需在高德控制台登记一次。

## 7. 测试与演示数据

- 测试数据统一以“【测试】”开头命名，演示时可明确区分。
- 种子数据脚本放 `server/src/main/resources/db/seed.sql`，至少 30 条物品，覆盖各分类与 499 / 500 / 501 米边界点。

## 8. 周会

- 每周一次，记录在 GitHub Issues 或 `docs/周记录/第N周.md`：本周完成、阻塞项、下周任务。
- 最终个人贡献按“成员—任务—PR 链接—测试或截图—结果”整理。
